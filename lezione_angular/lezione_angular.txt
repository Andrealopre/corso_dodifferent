LIVELLI ARCHITETTURALI

Le parti fondamentali di un'applicazione sono 3:
    - Parte logica
    - Interfaccia
    - Dati

Le applicazioni ad un livello creavano problemi di rete in quanto non potevano essere distribuite. Erano delle strutture
monolitiche.

Web server
Apache o internet information server. Gestisce lo scambio delle pagine html e gli utenti ricevono ciascuno la 
propria pagina hmtl.

TCP/IP - HTTP
Sono dei protocolli. In particolare il TCP/IP è un protocollo di rete. HTTP invece è il protocollo applicativo, 
sbaragliando tutti gli altri protocolli esistenti.

Il ruolo del protocollo di rete è quello di garantire che la comunicazione con applicazioni distribuite siano come se
queste fossero in un unico ambiente, comportandosi come un dispositivo unico.

ARCHITETTURA WEB/HTTP
Gli attori principali di questa architettura sono:
                        
    Il browser-->request-->Server web              DBMS
              <--request<--Logica                  Database               
                           Presentazione   

La request è il componente che porta le comunicazioni del browser verso il server. E' lo strumento usato dall'HTTP
client per trasmettere dati al server. Nelle request ci sono le query string. La response è invece in forma 
html/javascript. HTTP non sa a chi sta rispondendo. Riceve le request e risponde. Tutto ciò che avviene lato server
funziona solo una volta, ovvero quando viene chiamata, ma poi non ricorda di aver fatto tale azione.

Le applicazioni web sono applicazioni non connesse e senza stato, ovvero che loro non ricordano. Le applicazioni web
sono degli automi che elaborano processi e basta. Il DBMS si occupa di mantere i dati.

Il precedente è il ciclo di vita della richiesta, che descrive il ciclo di vita dell'http.

Content type: il tipo classico è di tipo text/html. Tutto il comportamento dell'http sono determinati dal content type.
Il browser è il punto debole dell'architettura perché non elabora: interpreta ma non è intelligente.

QUERYSTRING
Il formato di come la request trasmette le informazioni e le indirizza ad un componente applicativo del server web.
In genere la querystring ha questa struttura:
    - https://indirizzoserver/risorsa
Il browser non fa parte dei livelli dell'architettura web, è solo uno strumento.

ANGULAR

Quando si lavora in java, si sta lavorando lato backend. Quando si lavora con angular è frontend. Le applicazioni
angular sono applicazioni web (frontend). Quando si usa angular si sta sviluppando un sito web.
Vantaggi: un sito web scritto con angular permette di usare il linguaggio typescript, quindi, anzichè usare html e
javascript, si può usare un linguaggio ad oggetti, molto più vicino alla logica di java. Angular gestice il DOM in un
modo semplice, avanzato e professionale.

Angular gira su una sola pagina html (index.html) anche detta single page.
Tutta la logica si basa sui componenti e view. Definita la single page, il resto diventa un puzzle, in base alle 
interazioni vengono avviate view e componenti. Ogni componente ha una parte di codice ed una parte html.
La parte html si chiama view, la parte di codice è typescript, che viene associato a una view. Il codice associato
alla view è il componente. Tutto il meccanismo da imparare consinste nel far comunicare la view e il componente.
Questa tecnina di comunicazione si chiama binding.
Il binding è unidirezionale se la comunicazione avviene dalla classe
verso la view o viceversa.
Quindi gli elementi e i comportamenti della view possono essere gestiti tramite la loro classe associata.
