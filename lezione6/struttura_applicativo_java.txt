1) Concetto di interfaccia (Tipo referenziale)
2) Polimorfismo per interfaccia

5) JDBC

Un'interfaccia è un elenco di metodi astratti. Ovvero, un elenco di metodi non implementati (senza corpo senza logica)
Le classi concrete sono le classi di default e non possiedono metodi astratti.
Le interfacce non hanno costruttori

package controller;

import java.util.ArrayList;
import java.util.Collection;
import java.util.LinkedList;
import java.util.List;

import repository.CrudService;
import repository.ICrudService;

public class Avvio {

	public static void main(String[] args) {
		// polimorfismo per interfaccia
		ICrudService crud = new CrudService();
		
		//Le liste si dovrebbero inizalizzare a null e in base alle necessità si aggiorna il tipo
		List<String> nominativi = null; 
		nominativi = new LinkedList<>();
		
		// vorrei dichiarare una variabile che accetti sia liste che set, si usa collection
		Collection<String> collezione = new ArrayList<>();
	}

}

JDBC usa le seguenti interfacce:
Connection conn = null;
PreparedStatement ps = null;
ResultSet rs = null;

Queste sono delle interfacce per sql in java

I try catch verranno usati per gestire le connessioni, qualora ci fossero dei problemi di sintassi in sql 
In un try catch si mettono prima i catch più specifici e in fondo a tutto si mette Exception
Il finally rappresenta il blocco di istruzioni che devono avvenire indipendentemente dall'accadimento dell'eccezione
Le connessione a db vanno moderate, basta un calo di tensione per corrompere un database. Per sicurezza, al di la di un'eccezione, con il finally si garantirebbe a prescindere la chiusura di 
connessione a db, e tutti gli oggetti coinvolti.
